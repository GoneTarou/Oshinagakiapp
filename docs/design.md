# デザインルール

## 目的と原則

会場での短時間・片手操作を前提に、配置番号を最も素早く認識できるUIにする。

- **明快さ**：情報の意味と操作結果を一目で分かるようにする
- **コンテンツ優先**：装飾より配置番号と巡回先情報を優先する
- **控えめな階層**：余白、背景色、控えめな影で情報を整理する
- **一貫性**：同じ役割の要素に同じ色・余白・操作方法を使う

Appleのデザイン思想を参照するが、Apple製品のUIを模倣することは目的としない。

## カラーシステム

色は役割で使い分け、色だけで意味を伝えない。

| 役割 | 用途 | 推奨トークン |
| --- | --- | --- |
| 背景 | ページ背景 | `base-100` |
| 表面 | カード・フォーム | `base-200` または `base-100` |
| 主操作 | 作成・共有などの主要ボタン | オレンジ（`primary`） |
| 補助操作・アクセント | 戻る、補足リンク、選択状態 | 青（`secondary`） |
| 配置番号 | 巡回先を即座に識別するバッジ | `error` |
| イチ推し | 注目すべき巡回先 | `warning` |
| 成人向け | 注意や遷移先の明示 | `neutral` と `🔞` 表記 |
| エラー | 入力不備 | `error` |
| 成功 | リスト作成完了 | `success` |

- 1画面内で主役となる強い色は、主操作と配置番号を中心に絞る
- メインカラーはオレンジとする。主要ボタンには白文字と十分なコントラストを確保できる濃いオレンジ（例：`#C2410C`）を使う
- アクセントカラーは青とし、補助操作・リンク・選択状態に使う
- 淡いオレンジ（例：`#FFF7ED`）は、補足情報や選択状態の背景にのみ使う
- 本文と背景のコントラストはWCAG AA以上を満たす
- 赤い配置番号バッジには配置番号テキストを必ず併記する
- 成人向けカードは通常画面に表示するが、初期状態ではカード内容を隠す
- 成人向けカードには配置番号と「🔞 成人向け」の注意表示を出す
- 「成人向けコンテンツを表示」の操作でカード内容を展開する

## タイポグラフィ

日本語・英数字ともにOS標準のサンセリフ体を使う。

```css
font-family: -apple-system, BlinkMacSystemFont, "Hiragino Sans", "Yu Gothic", sans-serif;
```

| 要素 | サイズ | 太さ | ルール |
| --- | --- | --- | --- |
| ページタイトル | 24px以上 | 700 | 1画面に1つ |
| セクション見出し | 18px以上 | 700 | 内容を短く表す |
| 本文・フォームラベル | 16px以上 | 400〜500 | 読みやすさを優先 |
| 配置番号 | 20px以上 | 700 | カード上部で最も目立たせる |
| 補足・注記 | 14px以上 | 400 | 単独で意味が通るように書く |

- 本文を12px以下にしない
- 配置番号は等幅ではなくてもよいが、数字と英字が判別しやすい太さを使う
- 文言は「作成する」「共有する」のように、操作結果が分かる動詞を用いる
- Webフォントは追加しない

## テーマ

- MVPではライトモードのみ対応する
- ダークモード用の配色・切り替え機能は実装しない

## 余白・間隔

基本単位は4pxとし、原則として4の倍数を使う。

| 用途 | 間隔 |
| --- | --- |
| アイコンと文字 | 4〜8px |
| ラベルと入力欄 | 8px |
| フォーム項目間 | 16px |
| カード内の要素間 | 12〜16px |
| セクション間 | 24〜32px |
| ページ左右余白（モバイル） | 16px |
| ページ左右余白（タブレット以上） | 24px以上 |

- 要素を罫線だけで区切らず、まず余白でグループを示す
- 関連する入力項目は同じカードまたは同じ余白のまとまりに置く
- フォームの主要ボタン前後には、誤タップを避ける十分な余白を確保する

## 角丸

角丸は控えめに統一し、情報のグループ化に使う。

| 要素 | 角丸 |
| --- | --- |
| ボタン・入力欄 | 8px |
| カード | 12px |
| バッジ | 9999px（pill） |
| モーダル | 16px |

- 1つのコンポーネント内では異なる角丸を混在させない
- 強い装飾目的の大きすぎる角丸は使わない

## 影と階層

影は、クリック可能な要素や前面に出る要素の階層を伝えるためだけに使う。

| 要素 | 影 |
| --- | --- |
| 通常カード | なし、またはごく薄い影 |
| 押下可能なカード | 控えめな影とホバー時の変化 |
| モーダル・ポップオーバー | 明確だが柔らかい影 |

- 通常カードを影だらけにしない
- 影ではなく背景色・余白・境界線で区別できる場合は、そちらを優先する
- ホバー効果は補助であり、タッチ端末で成立する操作にする

## コンポーネント設計

### ボタン

- 主要操作は1画面につき原則1つだけ `primary` を使う
- タップ領域は最低44px × 44pxを確保する
- 破壊的操作はMVPでは作成しない。将来追加する場合は `error` 色と確認手順を使う
- アイコンだけのボタンには `aria-label` または見えるラベルを付ける

### フォーム

- ラベルはプレースホルダーで代用せず、入力欄の外に常時表示する
- 必須入力は「必須」と明示する
- エラーは該当入力欄の近くに表示し、色だけに依存しない
- `source_url` は任意入力と明示する
- 1リスト最大20件、イチ推し最大1件を入力画面でも案内する

### 巡回カード

- daisyUIの `card-compact` を基礎にする
- カード上部に配置番号の `badge-error` を置く
- イチ推しの場合は `👑 推し` の `badge-warning` を併記する
- 外部ポストURLがない場合でも、配置番号カードとして成立させる
- 通常の閲覧画面では成人向けカードの内容を初期表示しない
- 表示順は登録順とする

### リスト表示

- 会場での確認を最優先し、左から右、上から下の順に読む
- 十分な画面幅では3列のグリッドを使う
- 狭い画面では文字・タップ領域を保つため、列数を減らして横スクロールを発生させない
- 共有URLとX共有操作は、作成直後と閲覧画面で分かりやすく提示する

### ロゴ・アプリアイコン

- ロゴ・アプリアイコンはユーザーが用意する
- 実装時は、提供されたアセットの色・余白・利用条件に合わせる

## アクセシビリティ

- 文字と背景のコントラストはWCAG 2.2 AA以上を目標にする
- 色だけで状態を示さず、文言・アイコン・形状を併用する
- キーボードだけで全ての操作ができ、フォーカス位置を明確に表示する
- フォームエラーは入力欄とプログラム上関連付ける
- 画像・アイコンには用途に応じた代替テキストを付ける。装飾目的なら空の代替テキストにする
- 画面拡大時にも、内容が隠れたり横スクロールを強制したりしない
- 動きは控えめにし、操作完了やエラーは視覚以外にも伝わる構造にする
- 成人向けランキングへのリンクには、遷移先が成人向けであることをテキストで明示する
- 成人向けランキングへの遷移時に、確認画面は表示しない

## 実装時の確認項目

- daisyUIの意味的な色トークンを使い、ページごとの独自色を増やさない
- モバイル幅で配置番号・フォームラベル・主要ボタンが読みやすいか確認する
- 200%拡大、キーボード操作、エラー表示を確認する
- 成人向けカードの内容が初期表示されず、「成人向けコンテンツを表示」で展開できることを確認する
